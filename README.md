# Анализ HR-бренда: Яндекс, Сбер и Газпром нефть

Проект по сбору, обработке и анализу данных о вакансиях трёх крупных российских компаний с фокусом на сравнение их HR-брендов через призму требований к кандидатам, зарплат и предлагаемых бенефитов.

## Обзор проекта

Цель проекта — провести конкурентный анализ рынка труда, изучив 2039 вакансий трех компаний: **Яндекс**, **Сбер** и **Газпром нефть**. Анализ выходит за рамки простого сравнения зарплат и фокусируется на том, как бизнес-модель каждой компании формирует её уникальную стратегию найма и ценностное предложение для сотрудников (EVP).

## Ключевые выводы

Выявлено три принципиально разных подхода к найму:

-   **Яндекс — «Магнит для опытных технарей»**
    -   **Фокус:** IT-разработка (25.2 % вакансий).
    -   **Стратегия:** Охота за специалистами уровня Middle/Senior с предложением высоких зарплат. Ставка делается на сложность задач и силу IT-бренда.
    -   **Бенефиты:** Лидер по наличию питания в офисе, что подчеркивает культуру технологичного комфорта.

-   **Сбер — «Империя лояльности и гибкости»**
    -   **Фокус:** Продажи и обслуживание (37.9%).
    -   **Стратегия:** Массовый наём, в том числе новичков, с фокусом на внутреннее обучение. Лидер по привлечению кандидатов без опыта.
    -   **Бенефиты:** Самый сбалансированный и щедрый соцпакет. Абсолютный лидер по гибкому графику (91.5%) и премиям (83.4%).

-   **Газпром нефть — «Кузница кадров и удержание»**
    -   **Фокус:** Инженерия и производство (40.3%).
    -   **Стратегия:** Лучшие условия для найма новичков и специалистов с опытом 1-3 года. Senior-позиции почти не публикуются в открытом доступе, что говорит о ставке на долгосрочное выращивание собственных кадров.
    -   **Бенефиты:** Стабильный соцпакет, ориентированный на фундаментальные потребности (ДМС, спорт).

## Пайплайн данных

Проект реализует ETL-пайплайн: от загрузки сырых данных до их анализа.

1.  **Извлечение (`Extract`)**: Модуль `api_connector.py`
    -   Получает список вакансий с `api.hh.ru` для трёх заранее заданных компаний (`company_id`: 1740, 3529, 39305) по 16 крупнейшим городам России.
    -   Для каждой найденной вакансии из списка запрашиваются детальные данные.
    -   Соблюдаются ограничения API (задержки между запросами).
    -   **Результат:** Сырые JSON-файлы (`vacancies_<id>.json`), сохраненные в `data/raw/`.

2.  **Трансформация (`Transform`)**: Модуль `data_parser.py`
    -   Загружает сырые данные из JSON-файлов.
    -   Извлекает ключевые поля: название компании, зарплата, опыт, город, профессиональная роль.
    -   **Извлечение бенефитов:** Парсит описания вакансий на предмет ключевых слов, соответствующих определенным категориям льгот (ДМС, обучение, спорт, ипотека и т.д.). На этом этапе трансформирует текстовое поле в набор бинарных признаков (есть/нет).
    -   **Результат:** Обработанный и очищенный датафрейм.

3.  **Загрузка и анализ (`Load & Analysis`)**: Jupyter Notebook `hr_brand.ipynb`
    -   Загружает итоговый CSV-файл с обработанными данными.
    -   Проводит разносторонний анализ, включая:
        -   Географию найма.
        -   Зарплатные вилки в разрезе опыта и компаний.
        -   Распределение требуемого опыта.
        -   Кластеризацию вакансий по профобластям (IT, аналитика, продажи и т.д.).
        -   Детальный анализ предлагаемых бенефитов.

## Установка и запуск

1.  **Клонирование репозитория:**
    ```bash
    git clone https://github.com/dashamoker/hr_brand_analysis
    cd hr_brand_analysis
    ```

2.  **Создание виртуального окружения (рекомендуется):**
    ```bash
    python -m venv venv
    source venv/bin/activate  # на Linux/macOS
    # или
    venv\Scripts\activate  # на Windows
    ```

3.  **Установка зависимостей:**
    ```bash
    pip install -r requirements.txt
    ```

## Использование

1.  **Актуализация данных (опционально):**
    Чтобы получить свежие данные с hh.ru, запустите скрипт сбора. Вы можете изменить список компаний или городов в файле `src/api_connector.py`.
    ```bash
    cd src
    python api_connector.py
    ```
    **Примечание о стабильности**: Модуль api_connector.py был разработан под конкретную версию API HeadHunter и строго зависит от структуры JSON-ответов. Поскольку API может меняться (и с момента разработки в него уже вносились изменения), работоспособность скрипта сбора данных на 100% не гарантируется. Аналитическая часть проекта, представленная в Jupyter Notebook, опирается на уже собранный и статичный набор данных.

2.  **Запуск анализа:**
    Откройте и выполните Jupyter Notebook `notebooks/hr_brand.ipynb`. Он использует предварительно обработанные данные для построения всех графиков и выводов.
